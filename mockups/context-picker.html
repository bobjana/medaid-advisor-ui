What changed

  1. Inline-left: the chip sits in the composer, left of the input, bottom-aligned (grows with the input).
  2. Chip → picker: it’s now a button with a caret, not a static pill. Pressing it opens a tree.
  3. Tree: All Schemes is the root. Each scheme has All plans + its plans. Schemes you haven’t selected stay collapsed.
  4. Selecting a node updates the chip instantly and applies to your next question.

Chip states

▦ All Schemes no filter — advisor will ask which scheme
▦ Discovery ▼ scheme-wide (all plans)
▦ Discovery › Executive Plan ▼ scheme + plan

Behaviour

  • Opens as a popover anchored above the chip (flips below when there’s room).
  • On narrow screens it becomes a bottom sheet.
  • Selected scheme auto-expands; other schemes stay collapsed.
  • Selecting a node applies it and closes the popover.
  • Expanding/collapsing via the twisty is not a selection — the popover stays open.
  • A visible ✕ closes without selecting (Esc also works, but isn’t the only way out).
  • “All Schemes” = clear context.

Open question — how the change reaches the agent

Context lives in the agent session, not the browser, so a silent chip change needs a small backend addition.

Option A (recommended): new POST /api/chat/context that appends a state delta setting selected_scheme / selected_plan — same pattern as the existing reset route. Chip changes silently; your next question is scoped. “All Schemes” clears the same keys.

Option B: no backend change — picking a node sends a normal chat turn (visible bubble + reply), like today’s scheme→plan flow. Noisier for a pure context switch.
