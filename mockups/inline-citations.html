I'm on Discovery KeyCare Plus — what hospital cover do I get, and how does it compare to Priority?
✚

KeyCare Plus — hospital cover

KeyCare Plus gives you unlimited hospital cover when you use the KeyCare network of hospitals, with no overall annual limit. The trade-off is network-only access: out-of-network admissions are not covered unless it is an emergency or pre-authorised.

What is included:

  • Unlimited hospital cover at KeyCare network hospitals — no annual limit, no day-to-day limits on in-hospital procedures.
  • 27 chronic conditions on the Chronic Illness Benefit, subject to registration before you claim.
  • Day-to-day benefits paid from a Medical Savings Account, not from the plan's risk pool.

How it compares to Priority

Priority is the entry-level KeyCare option and is priced slightly lower, but its hospital cover is limited to a R2,2 million annual limit across the Priority network. Both plans share the same KeyCare network and the same chronic-condition list.

If you are likely to need one or more hospital admissions a year, KeyCare Plus is the safer choice because the hospital benefit has no ceiling.

How it would work

  1. Build a per-message registry from the citations event (already deduped by URL).
  2. In the markdown renderer, intercept links whose href matches a registry url — with a fallback match on decoded uri or filename — and render them as a numbered marker instead of a link.
  3. Render the numbered list at the foot of the bubble; the number scrolls to it, and the number in the list scrolls back to the first inline use.
  4. Prompt change: ask the model to cite every grounded claim, not just once per answer.

Decisions I need from you

1. Numbering order — “First use” (shown) vs “Retrieval rank”

First use: numbers match reading order, nothing is listed that isn't cited — but the list renumbers when it settles and sources arrive before the text finishes streaming (the function_response precedes the answer), so numbers briefly shift.

Retrieval rank: number = RAG rank, stable for the whole turn, list is complete from the first byte — but you can get a list of 4 where only 1 and 3 are cited inline.

2. Retrieved-but-never-cited documents

Shown above as a muted “Also consulted” group (no number). Alternatives: hide them, or number everything and accept unused numbers. I'd hide them once streaming settles, keep them while streaming.

3. What the row says

4. Hover preview

5. Wording

Edge cases the mockup covers

  • Long filenames — discovery-health-medical-scheme-comprehensive-plan-guide.pdf truncates in the row (full name in the title tooltip). Try Narrow and the chips view.
  • Repeated citation — the same document cited 4× shares one number.
  • Multiple at one claim — two adjacent numbers render as 1,2.
  • Model forgets to inline-link — graceful fallback: the list still renders (old behaviour), just unnumbered. Nothing breaks.
  • URL matching — the model sometimes re-encodes or truncates the long download URL. Matching must normalise (decode, compare uri query param, then filename) rather than comparing raw strings.
  • Sources without a download link — non-gs:// sources produce no Download: line (agent.py:206); those rows must be non-clickable.
  • Filthy filenames in the corpus — e.g. “Bestmed 2026 Comparative Guide (1).pdf”, “discovery-health-medical-scheme-executive-plan- guide 2026.pdf”. Worth a display-title cleanup (strip extension, title-case, drop (1)).
  • Zero citations — pricing answers come from list_plans/get_plan_pricing, not RAG, so the sources block must disappear entirely, not render empty.

Three things I'd fix while in there

  • CITATION_BLOCK_RE requires the three lines in exact order with no tolerance — a single missing Download: line silently drops the source. Make Download: optional and the URI line tolerant.
  • An answer spanning two tool calls replaces the citation list rather than merging it (finalCitations = event.citations). Merge + dedupe per turn.
  • Deep-links: /download?uri=… opens page 1. If we ever want “jump to the cited page” we need page metadata from the RAG chunks — not available today.
